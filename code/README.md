# 稠油注采井连通性智能分析 —— 最佳滞后天数预测

## ① 算法名称

**因果滞后谱分段决策模型**

Causal Lag-Spectrum Segmented Decision Model（CLSD）

## ② 方法简介

### 0. 训推边界与合规设计

本方案在代码层面保证以下几点：

1. **训练阶段只读 `train/`。**
   * `predict.py` 先只用 `train/` 目录（训练标签 + 训练期注采数据）构造训练特征并训练全部模型。
   * `test/` 目录下的注采数据在训练完成后的推理阶段才读取，测试模板只用来确定要预测哪些行和输出格式，本身不含标签。
   * 训练完成后，模型、特征工程、校准系数与判定规则即全部确定。
2. **特征严格因果。** 日期 t 的特征只使用 t 及以前的注采数据，以及早于 t 的训练标签：
   * 只用尾随窗口，不用中心窗、扩展窗和全序列统计量；
   * 采出缺失只做"向前"补齐（见第 2 节）。
   * 历史标签偏置（第 5 节）只读取`train/optimal_lag_days.csv` 中日期早于 t 的标签；
   * 核查：对全部训练样本分别用"只含训练期数据"和"含测试期数据"两种数据范围构造特征，924 维逐值相同。
3. **逐样本独立推理。** 每个测试样本只用它自己的（井组, 采出指标, 日期）对应的注采数据，经固定模型和固定规则给出结果。
   * 不使用任何测试集统计量（分布、分位数、排名、均值等）；
   * 不使用其他测试样本的预测结果，也不做跨样本的平滑、归一化、投票或名额分配。
   * 核查：只保留三分之一的测试行、并打乱行序重新运行，结果与完整运行逐行相同。
4. **参数只用训练期数据确定。** 所有阈值与参数都在训练期数据上用前向评估确定，集中写在 `config.yaml` 中。
   * 没有使用评测反馈反推任何测试标签，代码中也没有写入任何从评测得到的信息。

### 1. 总体思路

评分函数为 `S = 60·Acc_seg + 0.3·max(0,100−30·MAE_short) + 0.1·max(0,100−2·MAE_long)`，
其中短段 / 长段按真实值 ≤3 / ≥4 划分，$MAE_{short}$ 在真实短段样本上计算，包含被误判为长段的样本。

换算到单个样本（N 为样本数，p 为真短段占比）：

| 情形 | 单样本代价 |
|---|---|
| 分段判错一次 | 60/N |
| 真短段样本每差 1 天 | 9/(pN) ≈ 20/N |
| 真长段样本每差 1 天 | 0.2/((1−p)N) ≈ 0.36/N |

后两者相差约 55 倍。因此预测拆成两步：

1. 模型给出三样东西：P(短段)、短段内取值 0–3 的分布、长段条件中位数；
2. 对每个样本，在 v ∈ [0, 45] 上最小化期望代价。

最优解的形态是：

* 判为长段的样本输出 4，最便宜的长段值，可以保护 $S_{short}$；
* 判为短段的样本输出 0–3 中期望绝对误差最小的值；
* 是否判短，取决于 P(短段) 与短段取值分布。短段取值大概率为 0 的样本被误判为长段时，要多付 4 天误差，因此在更低的 P(短段) 下就应判短。

### 2. 序列构造

* **注汽序列**：注入表中该井组记录的 `INJ_VOL_DAILY` 之和；当天没有有效记录时按 0 处理。注入表中偶尔出现本井组生产井自身（吞吐井）的注汽记录（如 G079/W338、G080/W334、G084/W337、G055/W303），这些井不是本井组的注入井，不计入。
* **采出序列**：井组信息表中 `WELL_PURPOSE = 生产井` 的井在该指标上的均值（井组没有生产井记录时取全部井）。井组声明了多口生产井、且其中有的井在其他井组充当注汽井时（G079、G080、G084），只取不充当注汽井的那口。

  以上两条只依据井组信息表 `well_group_info.csv` 的井别，是固定的数据预处理规则。

  训练阶段只读 `train/` 下的井组信息表，推理阶段把 `test/` 下的井组信息表合并进来，这样测试数据带来训练期没有的井组（新井组、新区块）时，仍能按井别正确构造序列。两份表相同时结果不变。

  缺失值的补齐方式分两种：

  * **秩相关特征族**：用线性插值补齐，但只用日期 t 及以前的观测。
    * t 当天有观测时，窗口内的缺失都夹在两个不晚于 t 的观测之间，直接线性插值；
    * t 当天缺失时，从最后一个观测起到 t 为止，以很小的斜率单调下降延续（每天下降 0.02 个标准差，标准差取最后观测前 90 天内的观测值）。
      原因：线性插值在缺失段内是严格单调的，秩相关只取决于缺失段内的时间先后，若平直延续，缺失段会变成一大段并列秩，
      与插值后的形态完全不同。对整段窗口都处在缺失段内的样本，这样得到的秩相关曲线与"两端观测之间线性插值"得到的完全一致；
    * t 之前没有任何观测时，该样本的这族特征留空。
  * **互相关配方库**：只做前值填充，首个观测之前记 0。

### 3. 特征

**(a) 窗口内秩相关滞后谱（355 维，`src/feature.py` 的 `build_lin_frame`）**

对每个（井组, 采出指标, 日期 t），在滞后 L = 0…45 上计算注汽与采出的秩相关。两侧都在**窗口内**取秩，并列时取平均秩。

* **固定窗收缩重叠 Spearman**：只取最近 W 天 `[t−W+1, t]`；滞后 L 时，注汽取前 W−L 天、采出取后 W−L 天。
  * W ∈ {75, 90, 105, 120}，另加 3 日尾随滑动平均版本（W = 75 / 90 / 105）；
  * 同时由 |ρ| 与 n = W−L 换算 t 检验的 −log10(p) 曲线。
* **尾随平移 Spearman**：采出窗取 `[t−W+1, t]`，注汽窗取 `[t−L−W+1, t−L]`，W ∈ {60, 90, 120}。
* **Kendall τ-b**：固定 90 天窗，含正态近似 p 值（与`scipy.stats.kendalltau` 一致）。
* **选滞后规则特征**：由 −log10(p) 曲线导出。
  * 与最优 p 值相差 k 个数量级以内的最小滞后，k = 0.5 / 1 / 1.5 / 2；
  * 首个达到显著水平的滞后，−log10 p ≥ 4 / 6 / 8，没有达到时取峰值处；
  * 近优滞后个数；
  * 短段最优与全局最优之差。

每条曲线压成 8 个标量：短段（L ≤ 3）峰值与长段峰值之差、全局 / 短段内 / 长段内 argmax、全局峰值、短段峰值、均值、最高两个取值之差。
W = 90 的 p 值曲线（含 3 日滑动平均版）、90 天尾随曲线与 Kendall 曲线另外保留完整的 46 点。

依据：在训练标签上用单条规则直接预测（最近 90 天固定窗收缩重叠、秩相关、取与最小 p 值相差 1 个数量级以内的最小滞后），分段准确率约 0.80，高于任何 Pearson / 余弦类规则（≤ 0.66），这说明标签对窗口内两侧同时取秩和采出缺失用插值补齐都很敏感。

**(b) 互相关配方库（431 维，`src/feature.py` 的 `build_frame`）**

* 注汽 4 个通道：前值填充、缺失填 0、是否注汽、逐日变化绝对值；
* 采出 2 个通道：前值填充、逐日变化绝对值；
* 4 种尾随窗：21 / 45 / 90 / 150 天；
* 2 种相关：|Pearson| 与 |余弦相似度|。

每条 |相关| 曲线压成 6 个标量，另保留"前值填充 × 前值填充 × 90 天 × |Pearson|"一条完整曲线，再加采出指标编码 1 维。窗口内方差为 0 时相关性记为缺失，避免台阶状序列产生 0/0。

**(c) 曲线短段形状（36 维，`shape_features`）**

由 (a) 中保留完整 46 点的 4 条曲线（W=90 的 p 值曲线及其 3 日滑动平均版、Kendall p 值曲线、90 天尾随曲线）派生，L=0…3 之间的逐级差分与 L3−L0、L4–8 最大值相对 L3 的抬升、L9–12 相对 L4–8 的抬升、L0 / L3 / L0–3 最大值与全局峰值之比。它们直接刻画短段内曲线是上升还是下降、峰值是否刚好越过 3，主要改善短段取值 0–3 的判断。

**(d) 注采窗口统计（102 维，`window_stats`）**

在 30 / 60 / 90 / 120 天尾随窗口内，统计注汽序列的注汽天数占比、有效记录占比、变化次数、距最近一次变化 / 首次变化 / 最近一次注汽的天数、变异系数、峰均比、取值个数、大幅跳变次数与位置、近 15 天均值与窗口均值之比。
采出序列的有效观测占比、距最近一次观测的天数、变异系数、1 日与 7 日自相关、取值重复率、趋势相关、日变化占比、大幅跳变次数、近 7 天的标准化偏离。
这些量描述"曲线在什么样的数据条件下得到"，帮助模型判断滞后谱的可信程度。均为无量纲或天数，不含绝对水平。

所有特征都不使用任何标签。

### 4. 模型

所有模型只用训练样本训练，参数见 `config.yaml`。样本按距训练末日的天数加半衰期 150 天的权重。
训练好的模型保存为 `models/model.pkl`，joblib 格式，含两个 ExtraTrees（二分类与 7 类）、两个 LightGBM 模型、锚点样本外概率、训练样本的 W=90 p 值曲线及特征列顺序。

* **分段分类器：两个 ExtraTrees**
  * 两个成员各 400 棵树，设置相同：每次分裂随机抽 10% 特征、叶子至少 3 个样本、缺失值填 −1。
    * 成员 1（随机种子 0）：短段 / 长段二分类，P(短段) 取类"短段"的概率；
    * 成员 2（随机种子 1）：7 类分类，类别为 0 / 1 / 2 / 3 / 4–9 / 10–25 / 26–45，P(短段) 取前 4 类概率之和。7 类目标让树在分裂时同时区分短段内的不同取值、长段内的远近，学到的划分与二分类不同。
  * 两个 P(短段) 取平均，记为 $p_{et}$。
  * $p_{et}$ 经固定的逻辑校准后作为 P(短段)：`z = −0.1753 + 1.1625 × logit(p_et)`，再加第 5 节的历史标签偏置。
  * 校准系数的来源见第 6 节。
* **锚点模型**：同样设置的两个 ExtraTrees，只用训练末日前 14 天及以前的标签训练，对训练期最后 14 天的样本给出样本外概率，用于第 5 节计算最后一个训练标签处的模型残差。它只在训练阶段使用训练数据，推理时不再训练。
* **短段取值 4 分类（LightGBM multiclass）**：只用真实短段样本训练，给出 `P(y = k | 短段)`，k = 0…3。300 棵树、学习率 0.03、每棵树抽40% 特征。
* **长段取值回归（LightGBM，L1 损失）**：只用真实长段样本训练，给出条件中位数，夹到 [4, 45]。

### 5. 逐样本决策

0. **历史标签项**（`src/model.py` 的 `history_terms`）：对样本（井组 g, 采出指标 i, 日期 t），取同一序列 (g, i) 在 t 之前的最后一个训练标签作锚点：
    * s = +1（锚点为短段）/ −1（锚点为长段），该序列没有训练标签时 s = 0、不做任何调整；
    * h = t − 锚点日期（天）；
    * r = 1(锚点为短段) − 锚点模型在锚点处的校准概率（锚点不在训练期最后 14 天内时 r = 0）；
    * c = max(0, corr(样本在 t 的 W=90 p 值曲线, 锚点日期的同一条曲线))，两条 46 点曲线的皮尔逊相关。锚点日期的曲线在训练阶段由训练数据算出并存入模型文件，t 处的曲线就是该样本自己的特征。
    * 分段 logit 偏置：
      `z ← z + s·Σβ_k·exp(−h/τ_k) + r·Σγ_k·exp(−h/ρ_k) + c·[ r·Σγ'_k·exp(−h/ρ'_k) + s·Σβ'_k·exp(−h/τ'_k) ]`
      * τ = (1, 3, 7)，β = (−0.0204, −0.0420, −0.0263)；ρ = (7, 15, 30)，γ = (0.0315, 0.1180, 0.2137)；
      * ρ' = (15, 60)，γ' = (0.1255, 0.2402)；τ' = (7, 30)，β' = (0.0622, 0.3043)。
      
      含义：t 处的滞后谱与锚点日期的滞后谱越相似，锚点的分段（以及模型在锚点处的残差）越可能延续，延续的时间也越长。若谱形已经变了，则只保留很短时间的延续。
    * 短段取值调整：锚点标签 v_a 为 0–3 时，`log P(v_a) ← log P(v_a) + Σ g_k·exp(−h/τv_k)`，再归一化，τv = (3, 7, 15)，g = (−0.1678, 0.0746, 0.5166)。

    这是对同一序列自身的历史标签的自回归利用，只用早于 t 的训练标签、t 及以前的注采数据，不用任何测试样本的信息。h 越大，调整越接近 0。
    `config.yaml` 中 `history.enabled: false` 可关闭全部历史标签项，`history.similarity.enabled`、`history.value.enabled` 可分别关闭后两部分。
1. P(短段) = sigmoid(z)，取下限 0.07，即 `P ← max(P, 0.07)`；
2. 按第 1 节的代价，在 v ∈ [0, 45] 上取期望代价最小的整数（`src/model.py` 的 `emit`）。

每一行只用该行自己的 P、短段取值分布和长段中位数，行与行之间互不影响。

### 6. 关键参数的确定方式、数据范围与依据

**评估方式**：全部参数只用 `train/` 的数据确定，使用 8 个前向评估单元，模拟测试期训练止于 2 月 28 日、预测其后 92 天。

* 切点与预测天数：
  * 2025-10-15、10-31、11-15、11-30，各预测其后 92 天；
  * 2025-11-30、12-15、12-31，各预测其后 46 天；
  * 2026-01-15，预测其后 44 天。
* 每个单元只用切点及以前的标签训练模型，在切点之后的训练期样本上评分。
* 另用切点 2026-01-31、02-14 两个单元检查最近时段。

| 代价换算中的短段占比 P_ASSUME | 0.42 | 取训练期真短段率附近的值，0.36 / 0.48 下得分变化 < 0.07 |
| 短段取值 / 长段回归的 LightGBM 参数 | 见`config.yaml` | 前向评估确定。短段取值模型比较了 150 棵 / 学习率 0.06 / 抽 20% 特征（v19）、抽 30% / 40% 特征、300 棵 / 学习率 0.03、半衰期 60 / 90 / 300 天等 8 组，选 300 棵 / 0.03 / 40%，9 个单元平均 +0.12 分，最近 4 个单元 +0.21 分。半衰期各组差异在 ±0.05 内，沿用 150 天 |

### 9. 泛化性、运行效率与落地设计

以下试验都在第 6 节的前向评估框架内进行（切点 2025-10-15、10-31、11-15、11-30，各预测其后 92 天；历史标签项关闭），只用 `train/` 的数据。

**(1) 跨区块泛化。** 数据含两个区块（区块1 有 93 个井组，区块2 有 19 个井组）。把一个区块当作"新区块"，训练时完全不用它的标签，只在它的样本上评分，再与训练含该区块数据的同一批样本比较。

| 留出方式 | 评估样本 | 训练样本 | 得分：训练含该区块 → 不含 | 分段准确率：含 → 不含 |
|---|---|---|---|---|
| 区块2 当作新区块（只用区块1 训练） | 12965 | 24195–25135 | 78.12 → 77.29 | 0.836 → 0.835 |
| 区块1 当作新区块（只用区块2 训练） | 14460 | 2385–3440 | 81.34 → 75.72 | 0.867 → 0.787 |
| 未见过的井组（按井组留出 1/3，切点 2025-11-30） | 9050 | — | 77.53 → 77.16 | 0.832 → 0.831 |

区块留出的得分与准确率为 4 个评估单元的平均，井组留出为切点 2025-11-30 的一个单元（3 折合并）。区块2 不参与训练时，分段准确率几乎不变，得分下降主要来自短段取值。只用区块2 训练时，训练样本不到全部的 12%。

特征不含井组编号、日历和绝对产量水平，全部是无量纲的相关性、形状与天数，所以模型学到的是"滞后谱 → 滞后天数"的映射，可以直接用于新区块。新区块没有历史标签时，第 5 节的历史标签项自动为 0。

**(2) 精度与算力成本。** 分段分类器（两个 ExtraTrees）占模型文件的 98% 与大部分训练时间。`config_lite.yaml` 提供轻量档，只改 ExtraTrees 的规模，其余完全相同：

| 配置 | 分段分类器 | 树节点数 | 模型文件 | 分类器训练用时（单线程） | 离线得分（4 单元平均） |
|---|---|---|---|---|---|
| 标准档 `config.yaml`（生成提交结果） | 400 棵 × 2，叶子 ≥ 3 | 656 万 | 280 MB | 257 秒 | 79.85 |
| 试验档 A | 200 棵 × 2，叶子 ≥ 3 | 328 万 | 145 MB | 134 秒 | 79.81 |
| 试验档 B | 100 棵 × 2，叶子 ≥ 5 | 122 万 | 63 MB | 63 秒 | 79.75 |
| 轻量档 `config_lite.yaml` | 50 棵 × 2，叶子 ≥ 10 | 38 万 | 26 MB | 29 秒 | 79.89 |

各档的离线得分差异都在评估噪声之内（约 ±0.1 分）。标准档保留原规模，是为了与已提交的结果逐字节一致。轻量档用于算力或存储受限的现场部署，`python predict.py --config config_lite.yaml ...`，模型另存为 `models/model_lite.pkl`，不覆盖标准档模型。

**(3) 置信度与数据质量标记。** 加上 `--detail_output <路径>` 可另存一份逐样本诊断表（不影响结果文件），含校准后的 P(短段)、置信度 max(P, 1−P)、短段取值分布、长段中位数、W=90 滞后谱的峰值与峰位、近 90 天注汽活跃度与采出观测占比，以及数据质量标记（`弱相关`：谱峰值 < 3；`采出观测不足`：近 90 天观测占比 < 0.5；`滞后谱无定义`：谱无法计算，例如注汽或采出在窗口内恒定）。前向评估中置信度与分段准确率的对应关系：

| 置信度 | 样本占比 | 分段准确率 |
|---|---|---|
| 高（≥ 0.9） | 50% | 96.8% |
| 中（0.7–0.9） | 33% | 80.5% |
| 低（< 0.7） | 17% | 58.3% |

低置信度或带数据质量标记的样本，建议转人工复核。

**(4) 并行。** `config.yaml` 的 `runtime.n_jobs`（或命令行 `--n_jobs`）控制并行度，缺省为 0，即自动取 CPU 核数（最多 8）。
* 特征构造按井组分块、多进程计算。特征逐行独立，分块不改变任何取值；多进程不可用时自动退回单进程。
* ExtraTrees 多线程训练。每棵树的随机种子在并行之前就已确定，树与树互不影响，得到的森林与单线程逐位相同；推理时固定单线程按顺序累加。
* 并行度只影响速度：`--n_jobs 1` 与 `--n_jobs 2` 的结果文件和模型文件都逐字节相同（已核对）。

## ④ 运行命令

```bash
python predict.py --data_dir ./data --output ./result/test_optimal_lag_days.csv
```

* `--data_dir`：数据目录，其下为与赛事下发完全一致的 `train/` 与 `test/` 两个子目录；
* `--output`：结果 csv 路径。也可给目录，此时自动生成 `test_optimal_lag_days.csv`；
* 可选 `--config`：参数配置文件，缺省为与 `predict.py` 同目录的 `config.yaml`；
* 可选 `--use_saved_model`：跳过训练，直接加载 `models/model.pkl` 推理。`models/model.pkl` 就是生成提交结果所用的模型，两种方式的结果逐字节相同。
* 可选 `--n_jobs N`：并行度，覆盖 `config.yaml` 的 `runtime.n_jobs`（0 = 自动，1 = 单进程单线程）。只影响速度，不影响结果。
* 可选 `--detail_output <路径>`：另存逐样本诊断表（置信度、滞后谱峰值、数据质量标记等，见第 9 节 (3)），不影响结果文件。
* 轻量档：`python predict.py --config config_lite.yaml --data_dir ./data --output ./result_lite/test_optimal_lag_days.csv`（见第 9 节 (2)，结果与标准档不同，不用于提交结果）。

一次命令完成全部流程：读训练数据 → 构造训练特征 → 训练并保存模型 → 读取测试数据、构造测试特征 → 逐样本推理 → 写结果，无需人工干预。

结果文件逐字节保留测试模板的 BOM、CRLF 换行、日期写法与行序，只填写最后一列（0–45 的整数）。

| `b1to2_*`、`b2to1_*` | 4 + 4 | 一个区块完全不参与训练，只在它的样本上评分 | 第 9 节 (1) 跨区块表 |
| `fold0–2_*` | 3 | 按井组名哈希留出 1/3 井组 | 第 9 节 (1) 未见井组 |
| `lite_t200_*`等 | 12 | 分段分类器 200 棵，100 棵、叶子 ≥ 5，50 棵、叶子 ≥ 10（轻量档） | 第 9 节 (2) 精度与成本表 |
| `abl_bank_*`、`abl_bank-rank_*` | 2 + 2 | 只用互相关配方库，配方库 + 秩相关滞后谱（切点 10-31、11-30 两个单元） | 特征族贡献65.6 → 78.5 → 79.1（全部特征） |

`summarize.py` 按置信度 max(P, 1−P) 分级统计基线的分段准确率，即第 9 节 (3) 的置信度表（高 50% / 96.8%，中 33% / 80.5%，低 17% / 58.3%）。

```bash
python finals_analysis/02_experiments/cache_features.py --data_dir ./data      # 生成 outputs/feats.pkl
python finals_analysis/02_experiments/run_jobs.py --data_dir ./data           
python finals_analysis/02_experiments/summarize.py                             # 生成 outputs/numbers_exp.json
```

`run_jobs.py` 可用 `--only <任务名>` 只跑指定任务，或用 `--part 0 --nparts 2` 与 `--part 1 --nparts 2` 在两个终端里分两路并行。

### (3) 决策与输出诊断：`03_diagnostics/`

**`decision_checks.py`**（输入为 `02_experiments` 的输出，只用训练标签）：

* 盈亏点：按评分规则折算，真短段每差 1 天的代价约 21.4，真长段约 0.345。P(短段) 超过约 1.58% 时，长段多报 1 天就不划算，概率下限为 0.07，所以判为长段时统一报 4 天。
* 长段中位数的作用：参与代价计算并写入诊断表。在 31 个任务的176,055 条预测上，把它分别换成 4 和 45 后重新决策，提交整数都是 0 行变化。
* 判为长段时统一报 v 天的得分：报 4 天 79.85，报 45 天 57.52，改报长段中位数为 61.44。
* 时间漂移：离训练截止 1–15 天，分段准确率 0.912，76–92 天，准确率0.823。
* 弱谱样本：滞后谱峰值低于 3 的样本占 22.4%，分段准确率 0.744（全体 0.848），占分段错误的 37.7%。

**`review_workload.py`**（输入为 `predict.py --detail_output` 写出的测试期诊断表）：

* 置信度与数据标记的占比。
* 复核量：低置信或带数据标记的样本占 38.7%，每天中位数 54 个。两者同时满足的占 7.2%，每天中位数 10 个。
* 同一序列由长段转为短段：共 202 次，每天中位数 2 次。
* 置信度与输出分段的关系：555 行（5.0%）报短段但 P(短段) 在 0.30–0.50，全部为低置信，没有报长段而 P(短段) ≥ 0.5 的行。
* 每周低置信与带标记的占比，用于无标签时的漂移监测。
* 单个井组的输出时间线，缺省为 G109 在 2026-04-17 至 04-22 的输出与 P(短段)。

```bash
python finals_analysis/03_diagnostics/decision_checks.py
python predict.py --data_dir ./data --output ./result/test_optimal_lag_days.csv --use_saved_model --detail_output ./result/detail.csv
python finals_analysis/03_diagnostics/review_workload.py --detail ./result/detail.csv [--group G109 --start 2026-04-17 --end 2026-04-22]
```

结果写到 `finals_analysis/outputs/decision_checks.json` 与 `review_workload.json`。
